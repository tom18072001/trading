## 3. P0 fixes (highest impact — unblock the core signals)

### Fix 1 — Foreign flow volume→value (`sector_ingest_service.py`)
`_parse_foreign_board` now reads `*_value` if present, else converts
`foreign_buy_volume`/`foreign_sell_volume` × price → value. KBS `price_board`
exposes volume, not value, so the old `*_value`-only read returned **0 for every
sector since 2026-04-16** → stealth `cond2_foreign` failed everywhere →
**ACCUMULATE could never fire**. A new single `_fetch_foreign()` makes one board
call instead of two (halves rate-limit pressure); the old methods stay as wrappers.

### Fix 2 — vnstock duplicate-trailing-row (`sector_ingest_service.py`)
`_fetch_constituent_daily` now `df[~df.index.duplicated(keep="last")]`. vnstock
intermittently returns the latest bar twice → `close == prev_close` → `sign=0`
→ `net_dollar_flow`/`up`/`down` all collapse to 0. The 2026-04-30 monkey-patch
is now permanent in source.

### Fix 3 — Ranker persistence (`rotation_ranker.py`, `rotation_model_service.py`)
`fit()` now pickles the **actual** trained estimator to `rotation_ranker_v0.pkl`
(was only writing a metadata JSON, so the model could never be reloaded). The
service loads the active model on init, so `predict_today()` **stops retraining
on every call**. Retrain deactivates prior runs by `model_name`.

### Fix 4 — §16.2 features + 20d target (`flow_feature_service.py`, `config.py`)
The 7 leading/stealth features (`flow_z20, flow_z60, foreign_streak,
foreign_hit_20d, stealth_score, flow_price_divergence, accumulation_age`) are now
in `FEATURE_COLS` (with neutral 0-fill) — the ranker was previously **blind** to
the early-flow edge even though those features were computed and stored.
`ROTATION_TARGET_HORIZON_DAYS` is now **20** (was 5) per §16.4.

**Verification:** 70/70 backend tests passed with all four edits applied; each
algorithm independently verified on synthetic data reproducing the exact bugs;
locked in by `tests/test_fixes_20260618.py`.

## 5. P1 — Backtest realism (`backtest_service.py`, `config.py`)

The old engine produced fantasy Sharpe. The rewrite adds the VN frictions from §18.2:

- **§18.2/7 T+2 settlement** — sale proceeds locked for `settlement_lag=2` sessions; capital can't recycle same-day.
- **§18.2/10 fees + tax** — per-trade `fee_bps=15`/side + `sell_tax_bps=10` on proceeds (was a flat daily constant). Exposes `total_cost_pct`.
- **§18.2/9 slippage + price band** — per-fill `max(0.3%, 0.5×ATR%)`; a sector that gapped ≥±7% on the entry day is unfillable and counted in `ceiling_floor_skips`.
- **§18.2/12 long-only** — short leg removed (VN cash can't short). `strategy="rotation_long_only"`.
- **§16.6 entry-timing** — `root_capture_ratio` (median entry/peak close across closed trades).

New config knobs: `BACKTEST_FEE_BPS / SELL_TAX_BPS / SLIPPAGE_MIN_PCT /
SLIPPAGE_ATR_MULT / PRICE_BAND_PCT / SETTLEMENT_LAG / LONG_ONLY`. The `run()`
signature is unchanged; the result dataclass gained fields (additive — the router
serializes via `asdict`, non-breaking). Tests added.

**Still pending (not in this batch):** the backtest entry signal still uses
`net_dollar_flow` rank, not the 20d ranker model; §18.2/11 portfolio-vol sizing
and §16.9 ACCUMULATE sizing rules remain.

## 6. Daily Insight refresh "time exceed" fix (`trader_agent.py`, `config.py`)

**Root cause:** the HTTP refresh is already async + polling (frontend waits up to
20 min), so "time exceed" meant the **background run never finished**.
`TraderAgent.analyze()` had **no enforced timeout** despite the docstring's
"60-second budget" claim — a stalled Claude SDK transport hung the `trader_agent`
stage until the 20-min frontend ceiling.

**Fixes:**
1. **Hard timeout** — `asyncio.wait_for(query, timeout=AGENT_TIMEOUT_SEC)` (default 120s). On timeout the agent returns a graceful invalid report and the pipeline still assembles the `/daily` payload, so the button **always completes**.
2. **Prompt optimization** — system prompt ~60% shorter with a compact one-line JSON schema; output capped to 3 buys / 2 avoids, reasoning ≤2 sentences; input candidates capped (10 buy / 6 sell). Caps enforced in code, not just prompt text.
3. **Default model → `haiku`** (was `sonnet`) for this scaffolded structured-JSON task — much faster; override with `AGENT_MODEL=sonnet`.

New config knobs: `AGENT_MODEL / AGENT_TIMEOUT_SEC / AGENT_MAX_BUYS / AGENT_MAX_AVOID
/ AGENT_MAX_BUY_CANDIDATES / AGENT_MAX_SELL_CANDIDATES`. Added
`test_analyze_enforces_hard_timeout`.

**Still pending:** the dominant refresh latency is the ~4-min KBS universe rebuild
(rate-limited). If clicks still feel slow, add a "light refresh" that reuses a
same-day snapshot and only re-runs the agent, and acquire a vnstock community API
key (60 rpm).
